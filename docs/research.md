# NixOS и декларативная установка программ для 3D-печати

## Аннотация

Исследование посвящено декларативному управлению программным обеспечением в NixOS. Практическая часть представляет собой конфигурацию для установки Blender, UltiMaker Cura и CHITUBOX Basic.

Цель проекта — описать состав приложений, зависимости и параметры запуска в едином наборе файлов, пригодном для повторного развёртывания. Программы интегрируются в меню рабочего стола.

Основное внимание уделяется модульной организации конфигурации, фиксации версий и подключению программного комплекта к установленной NixOS.

## 1. Цель и задачи исследования

Ручная установка программ требует учёта выбранных версий, библиотек и параметров запуска. При переносе на другой компьютер неполное описание этих действий затрудняет повторное развёртывание.

Декларативный подход предполагает описание требуемого состояния в конфигурационных файлах. В данном проекте конфигурация определяет три приложения, их зависимости и настройки запуска. На её основе NixOS формирует программное окружение.

Для достижения цели определены следующие задачи:

1. Изучить установку пакетов и управление зависимостями в NixOS.
2. Определить состав и версии программного комплекта.
3. Подготовить недостающие описания пакетов.
4. Объединить приложения в один подключаемый модуль.
5. Закрепить версии и источники загрузки.
6. Подготовить сценарий подключения комплекта к существующей конфигурации NixOS.

Гипотеза исследования: фиксация состава пакетов, зависимостей и параметров запуска в конфигурации сокращает объём ручных действий при повторной установке.

## 2. Основные принципы NixOS

### Nix, nixpkgs и NixOS

В архитектуре системы выделяются следующие компоненты:

| Название | Назначение |
|---|---|
| Nix | Инструмент, который получает, собирает и хранит программы вместе с их зависимостями |
| nixpkgs | Коллекция рецептов сборки и подготовки программных пакетов |
| NixOS | Операционная система, в которой Nix используется для построения системной конфигурации |

Настройки NixOS записываются на языке Nix. Отдельный подключаемый файл с настройками называется **модулем**. В проекте модуль `three-d.nix` объединяет три приложения.

### Хранение программных пакетов

Nix хранит пакеты в каталоге `/nix/store`. Пакеты размещаются по отдельным путям, что позволяет сохранять разные версии библиотек без взаимной замены файлов.

Объекты хранилища рассматриваются как неизменяемые. Изменение описания приводит к подготовке нового результата с сохранением предыдущего окружения.

### Поколения системной конфигурации

Поколение — сохранённый вариант системного окружения. Команда `nixos-rebuild switch` строит и применяет конфигурацию. К предыдущему сохранённому поколению можно вернуться:

```bash
sudo nixos-rebuild switch --rollback
```

Такой откат не возвращает содержимое пользовательских документов и исходных файлов конфигурации. Для них нужны отдельные копии. Принципы настройки и поколений описаны в [руководстве NixOS](https://nixos.org/manual/nixos/stable/).

## 3. Воспроизводимость и фиксация зависимостей

В рамках исследования различаются три уровня воспроизводимости.

| Уровень | Содержание |
|---|---|
| Конфигурация | Используются те же Nix-файлы, версии пакетов и настройки запуска |
| Программные пакеты | Получены ожидаемые пакеты и зависимости; строгая проверка потребовала бы сравнить результаты независимых сборок |
| Функционирование приложений | Приложения запускаются, отображаются в меню и показывают рабочее окно |

Совпадение конфигураций не предполагает полного совпадения состояния компьютеров: драйверы, учётные записи и пользовательские данные могут различаться.

В строгом смысле воспроизводимая сборка означает возможность независимо получить побитово одинаковые файлы из одинаковых исходных данных. Такое определение даёт [проект Reproducible Builds](https://reproducible-builds.org/docs/definition/).

В проекте используются готовые дистрибутивы производителей, для которых описаны правила получения и подготовки пакетов. Фиксация этих входных данных обеспечивает повторное использование выбранного набора, однако не равнозначна независимой сборке всех приложений из исходного кода.

### Фиксация версий

В `workstation/nix/flake.nix` указан конкретный снимок nixpkgs. Файл `flake.lock` сохраняет сведения об этом снимке, включая его контрольную сумму. Такой набор файлов называется **flake**. Его назначение описано в [документации Nix](https://nix.dev/manual/nix/latest/command-ref/new-cli/nix3-flake.html).

Для Blender и CHITUBOX также указаны адреса архивов и их SHA-256 — контрольные суммы, по которым проверяется содержимое скачанных файлов. Версия Cura и её источник заданы в выбранном рецепте nixpkgs.

Файл `pinned.nix` использует закреплённый nixpkgs только для набора приложений. Системные настройки и основной набор пакетов целевой ОС сохраняются. Таким образом, конфигурация приложений отделена от конфигурации компьютера.

Для повторения конкретного состояния нужны и та же версия файлов проекта, и тот же `flake.lock`. Последняя версия в ветке GitHub со временем может измениться. Также сохраняется зависимость от доступности файлов производителей и серверов загрузки Nix.

## 4. Состав программного комплекта

Практическая часть размещена в каталоге `workstation` закрытого репозитория GitHub. Комплект предназначен для подготовки 3D-моделей и заданий печати в установленной NixOS.

| Программа | Версия | Назначение |
|---|---|---|
| Blender | 3.6.23 LTS | Создание и изменение 3D-моделей |
| UltiMaker Cura | 5.12.1 | Подготовка моделей к печати пластиковой нитью |
| CHITUBOX Basic | 2.3.1 | Подготовка моделей к печати фотополимерной смолой |

Cura и CHITUBOX относятся к слайсерам: они разбивают модель на слои и готовят задание для принтера. Наличие обоих приложений позволяет подготовить окружение для двух разных способов 3D-печати.

Комплект включает приложения, необходимые зависимости и записи меню с названиями и значками. Профиль принтера, материал и параметры печати задаются пользователем после установки.

## 5. Структура и реализация проекта

Реализация разделена на описания пакетов, системные модули и установочный сценарий.

| Файл или каталог внутри `workstation` | Назначение |
|---|---|
| `nix/packages/blender-compat.nix` | Получение Blender 3.6.23, библиотеки и запуск |
| `nix/packages/chitubox.nix` | Получение CHITUBOX, окружение для запуска и пункт меню |
| `nix/packages/extract-qtifw.py` | Извлечение файлов из установщика CHITUBOX |
| `nix/modules/three-d.nix` | Включение всех трёх приложений в системный набор |
| `nix/modules/pinned.nix` | Выбор закреплённой коллекции пакетов для приложений |
| `nix/flake.nix`, `nix/flake.lock` | Точка входа проекта и фиксация зависимостей |
| `scripts/install.sh` | Резервное копирование, подключение модуля и применение настроек |

Рецепт Cura уже есть в nixpkgs, поэтому отдельный рецепт в проекте не создавался. В модуле используется пакет `cura-appimage`.

### Подключение набора к системе

Подготовленный установщиком файл подключает модуль и активирует набор приложений:

```nix
{ ... }: {
  imports = [ ./nix/modules/pinned.nix ];
  programs.threeD.enable = true;
}
```

Фрагмент применяется внутри каталога, созданного установщиком. Параметр `imports` подключает модуль, а `programs.threeD.enable` управляет включением комплекта.

Внутри `three-d.nix` приложения добавляются в `environment.systemPackages`, то есть в общий список программ системы. Там же включается поддержка графики.

### Зависимости и окружение запуска

Библиотека — готовый программный компонент, который используется приложением, например для вывода окна, работы со шрифтами или графикой.

Сторонняя Linux-программа часто ожидает найти такие компоненты в привычных каталогах. В NixOS пути устроены иначе. Для Blender и CHITUBOX используется `buildFHSEnv`: он подготавливает окружение с привычными для программы путями. Сами библиотеки при этом выбираются через Nix-рецепт. Этот механизм описан в [руководстве nixpkgs](https://nixos.org/manual/nixpkgs/stable/#sec-fhs-environments).

Основные группы зависимостей:

| Компоненты | Назначение |
|---|---|
| `libGL`, `libGLU` | Работа с 3D-графикой |
| `libx11`, `libxcb` и связанные библиотеки | Взаимодействие графической программы с оконной системой |
| `fontconfig`, `freetype` | Поиск шрифтов и отображение текста в CHITUBOX |
| `libxkbfile`, `xkeyboard-config` | Данные и функции для обработки ввода с клавиатуры |
| `krb5` | Предоставляет библиотеку `libgssapi_krb5.so.2`, используемую компонентами CHITUBOX |
| Python и 7-Zip | Извлечение содержимого установщика CHITUBOX при подготовке пакета |

Python и 7-Zip используются на этапе подготовки пакета.

Cura использует общее окружение AppImage из nixpkgs. Его состав определяется выбранным рецептом и средствами поддержки AppImage.

### Основные этапы реализации

1. Определены версии приложений и источники дистрибутивов.
2. Подготовлены собственные рецепты Blender и CHITUBOX; для Cura подключён пакет `cura-appimage` из nixpkgs.
3. Создан общий модуль приложений с закреплённым набором зависимостей и пунктами запуска в меню.
4. Разработан установочный сценарий, который сохраняет конфигурацию целевой системы и подключает к ней модуль.

Рецепт Blender использует официальный архив программы. Для CHITUBOX предусмотрены извлечение файлов из установщика производителя и подготовка окружения запуска.

## 6. Установка программного комплекта

Для установки требуется установленная NixOS x86_64 с графическим окружением, доступом к сети и правами `sudo`. Установочный сценарий подключает приложения к существующей ОС.

Для первоначальной установки в систему со стандартным файлом `/etc/nixos/configuration.nix`:

```bash
cd ~
nix-shell -p git --run 'git clone https://github.com/AcronimD/nixos.git'
sudo bash ~/nixos/workstation/scripts/install.sh
```

Репозиторий закрытый, поэтому требуется доступ к нему. Если каталог `~/nixos` уже существует, повторно выполнять команду клонирования в тот же каталог не нужно.

Установщик:

1. Проверяет, что запущен на подходящей NixOS.
2. Сохраняет резервную копию текущих настроек.
3. Копирует файлы набора в `/etc/nixos/workstation-apps`.
4. Подключает модуль к существующей конфигурации.
5. Строит и применяет системное окружение.
6. Проверяет наличие команд запуска и файлов меню.

Исходные настройки системы сохраняются в `configuration.before-workstation.nix`. Файл `configuration.nix` становится точкой подключения этих настроек и модуля приложений. После такой установки настройки самой ОС нужно редактировать в сохранённом файле.

Для систем, управляемых через flakes, применяется режим `--prepare-only`, затем модуль подключается к существующей конфигурации системы. Порядок установки приведён в основном README.

Запуск приложений выполняется из меню «Графика» или командами `blender`, `cura`, `chitubox`. Пункты меню устанавливаются пакетами, поэтому не нужно создавать ярлыки вручную.

Для обновления закреплённой программы меняют её описание и снова применяют конфигурацию. Обновление через собственный интерфейс приложения не обновляет Nix-рецепт.
